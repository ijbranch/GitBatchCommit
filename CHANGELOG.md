## [Unreleased]

### Fixed
- **A batch could commit and push the WRONG repository.** `btnCommitPushClick` counted the matching rows, showed a modal confirmation, then re-filled a fixed-size array sized by that first count — and iterated it with `High()`. A background refresh publishing a new status while the dialog was open changed how many rows matched: fewer left trailing zeros in the array, so the loop ran `CommitAndPush` against repository index **0** with another repository's message; more overran the array, which Release builds did not range-check. The target list is now built once, as paths, after the confirmation (2026-09-05) — `MainFrm.pas`
- **The whole manager API is addressed by repository PATH rather than by array index.** `RemoveRepository` shifts the array down, so every index a batch was holding became off-by-one — and `PopulateListView` deliberately refuses to rebuild during a batch, so nothing repaired them. With `Application.ProcessMessages` in the batch loops and Remove Selected still enabled, a force-push batch could act on the repository next door. `CommitAndPush`, `PullRepository`, `PushRepository`, `ForcePushRepository`, `ResolveConflictsKeepLocal`, `CreateBackupBranch`, `GetIncomingChanges`, `SetRepositoryVisibility`, `GetRepoProvider`, `SetRepoGroup`, `MigrateRepository`, `RefreshStatus` and `RemoveRepository` all take a path now (2026-09-05) — `uGitRepoManager.pas`, `MainFrm.pas`
- **Use-after-free between the UI and the refresh workers.** The `Repos` property handed out the manager's live array, which the UI read unlocked while `TParallel` workers assigned `Branch`, `StatusText` and `Version` — managed strings, so the reader could add-ref a block the writer had just freed. It is replaced by `SnapshotAll` / `GetRepoSnapshotByPath` / `SetRepoSelected`, and the form works from a main-thread-owned `FRepoCache` (2026-09-05) — `uGitRepoManager.pas`, `MainFrm.pas`
- **Closing the window mid-operation freed the repository manager under a running worker.** The shutdown wait was capped at 90 seconds and its outcome was never checked, so `FreeAndNil( FRepoManager )` ran regardless — and a single unreachable remote comfortably outlasts that budget. A new `FormCloseQuery` refuses to close while work is in flight and offers to cancel; `FormDestroy` now waits without a deadline (2026-09-05) — `MainFrm.pas`, `MainFrm.dfm`
- **`TThread.RemoveQueuedEvents( nil )` removed nothing.** Both RTL overloads test the thread or method against nil, so for the `TThread.Queue( nil, … )` form used throughout, no callback was ever withdrawn and a queued `Log` or list update could run against a freed form. Replaced with an `FShuttingDown` flag that every queued closure checks (2026-09-05) — `MainFrm.pas`
- **`Application.ProcessMessages` removed from `Log`.** It pumped the message queue on every logged line, including from inside worker synchronisation callbacks, re-entering arbitrary UI handlers mid-batch. The batch loops that want responsiveness still pump explicitly (2026-09-05) — `MainFrm.pas`
- **The Git Client Path setting was used as `git.exe` whatever it pointed at**, while the settings prompt asked for a GUI client by name (`Fork.exe`). `CREATE_NO_WINDOW` suppresses a console, not a GUI, so every call burned the full 60-second timeout and every repository reported as an error. The path is honoured only when its filename is `git.exe`; the prompt has been corrected (2026-09-05) — `uGitRepoManager.pas`, `MainFrm.pas`
- **`--force-with-lease` was disarmed by this application's own background fetch.** `GetAheadBehind` runs `git fetch` on every status refresh, which advances the remote-tracking ref the lease compares against — so by the time the user clicked Force Push the lease passed and a colleague's commits were destroyed. `TRepoInfo.RemoteSHA` now records the upstream commit as the row's status was determined, and the push names it explicitly (`--force-with-lease=<branch>:<sha>`) (2026-09-05) — `uGitRepoManager.pas`
- **The commit conflict guard was skipped whenever `git status` failed or timed out.** It was one `and` chain, so an indeterminate state made the whole condition False and execution fell through to `git add -A` — publishing conflict markers to the remote, the exact failure the guard exists to prevent. Split into separate refusals, with a detached/unborn HEAD refused as well (2026-09-05) — `uGitRepoManager.pas`
- **Worktrees and submodules were permanently unusable.** `.git` is a *file* there, not a folder, so `TDirectory.Exists` reported every such repository as an error, the `MERGE_HEAD` probes could never fire, and `ResolveConflictsKeepLocal` returned **True** while doing nothing. Git is now asked, via `rev-parse --absolute-git-dir` and `--is-inside-work-tree`; `sequencer/todo` was added to the in-progress set (2026-09-05) — `uGitRepoManager.pas`
- **A repository whose changes were misjudged as build artifacts was dropped from the batch silently**, while the summary still said "n of n successful". Renames are now judged on both sides (`R old -> new` tested only the destination, so the deletion of the source was never committed), `.exe` and `.hpp` are no longer treated as build output, `android/` and `linux64/` only count with a configuration folder beneath them, quoted paths are unescaped rather than merely unquoted, and an unparseable line counts against the conclusion. the status text now reads "Clean - build output only", so the repository is visibly excluded rather than silently omitted (2026-09-05) — `uGitRepoManager.pas`
- **Untracked-only repositories reported Clean for anyone with `status.showUntrackedFiles=no` set**, so brand-new files were never committed and nothing said so. Git is now invoked with `-c status.showUntrackedFiles=normal` (2026-09-05) — `uGitRepoManager.pas`
- **`MigrateRepository` had no rollback and lost remote-only branches.** A failure after `remote rename origin` left the repository with no `origin`, or with `origin` on an empty new remote while the real one hid under an alias — and every later Commit & Push then pushed to the wrong place. Steps 4-7 are wrapped so any failure restores the original remotes; branches that existed only on the old remote are recovered before `push --all`; an existing remote named `codeberg`/`github` is no longer silently deleted; the provider is written back by path (2026-09-05) — `uGitRepoManager.pas`
- Nothing staged no longer aborts the push — `git commit` exits 1 in that case, which meant a repository with committed-but-unpushed work could not be pushed by Commit & Push at all (2026-09-05) — `uGitRepoManager.pas`
- The version tag now bypasses the 30-second scan cache. That cached value decides the tag that gets **pushed**, so a version bumped shortly before the commit was tagged with the previous number, or skipped because that tag already existed. The cache stamp is also compared exactly rather than with `>=`, which could never go backwards and pinned a stale version permanently (2026-09-05) — `uGitRepoManager.pas`
- `GetIncomingChanges` compares against the branch's configured upstream (`@{upstream}`) instead of a hard-coded `origin/<same name>`, which produced a wrong diff — reported as "no incoming changes" — for any branch tracking something else (2026-09-05) — `uGitRepoManager.pas`
- **Four status row colours painted the wrong colour.** A `TColor` literal is `$00BBGGRR`; these were written in RGB order, so Modified rendered pale cyan, Pull Required light blue, Push Required pale yellow and Diverged pink — Modified and Push Required effectively transposed (2026-09-05) — `MainFrm.pas`
- The new-repository dialog is captioned for the host it is actually creating on. It is shared by the Codeberg and GitHub flows and by migration in both directions, and its DFM caption said "Create Codeberg Repository" in every one of them (2026-09-05) — `uCodebergDialog.pas`, `MainFrm.pas`
- The new-repository dialog validates in `OnCloseQuery` instead of after `ShowModal` returned. A blank name previously produced a warning and then a False result, which every caller reads as "cancelled" — silently discarding the description and private flag the user had just entered (2026-09-05) — `uCodebergDialog.pas`
- `git ls-files --deduplicate` — during a content conflict the same path is printed once per index stage, so the Tracked column read three times its real value (2026-09-05) — `uGitRepoManager.pas`
- `ParseOwnerRepo` strips trailing slashes before the `.git` suffix; `…/repo.git/` used to yield `repo.git`, so every API call 404'd as "not found or no permission" (2026-09-05) — `uGitRepoManager.pas`
- `DetectRemoteProvider` compares the URL **host** instead of substring-matching the whole string, which classified `https://gitea.internal/mirrors/github.com-backup.git` as GitHub (2026-09-05) — `uGitRepoManager.pas`
- `GetAheadBehind` requires both `rev-list` fields to be all-digits before trusting them. stderr is merged into stdout, so one warning line ahead of the counts silently yielded 0/0 and the repository reported Clean while the remote was ahead (2026-09-05) — `uGitRepoManager.pas`

### Security
- **A DPAPI failure no longer writes the access token in plain text.** `ProtectSecret` returned the secret unchanged when encryption failed, so an unloaded profile — `RunAs /netonly`, a scheduled task, a damaged protect store — wrote a live token into the roaming config unmarked, and every later load accepted it as a legacy value. The state was permanent and completely silent. It now reports failure, the token is omitted from the file, and the settings dialogs say so instead of logging "credentials updated" regardless (2026-09-05) — `uGitRepoManager.pas`, `MainFrm.pas`
- **A repository's own `.dproj` could inject arguments into `git push`.** `GetProjectVersion` took the `FileVersion` value verbatim and it reached `git tag` and `git push` wrapped in nothing but quotes, so an embedded quote closed the quoting and the remainder became further arguments to Git. The version must now match `^\d+(\.\d+){0,3}$`, and `--` terminates option parsing at each sink (2026-09-05) — `uGitRepoManager.pas`
- **Adding an untrusted repository folder was code execution on the next refresh.** Git reads `core.fsmonitor`, `core.sshCommand` and `core.hooksPath` from the scanned repository's own config, and `safe.directory` does not fire for files the user owns. All three are now overridden on every invocation (2026-09-05) — `uGitRepoManager.pas`
- **`git` is resolved to an absolute path once via `SearchPath`.** `CreateProcess` with a bare name searches the image directory and the process **current directory** before `PATH`, and the settings browse dialog could move the current directory — it now sets `ofNoChangeDir` (2026-09-05) — `uGitRepoManager.pas`, `MainFrm.pas`
- DPAPI is called with application-specific entropy and `CRYPTPROTECT_UI_FORBIDDEN`. Without entropy the blob is decryptable by any process running as the same user with a three-line call, which is exactly what a credential sweep of `%APPDATA%` does. A blob written by an earlier build is still read, by retrying the decrypt without entropy, and is re-written with entropy on the next save (2026-09-05) — `uGitRepoManager.pas`
- **A stored secret that cannot be decrypted is never overwritten with an empty value.** A load that silently yields nothing, followed by the save-on-exit, is how an upgrade destroys a credential outright — the same failure the `FConfigLoaded` guard already prevented for the repository list. The original ciphertext is written back untouched unless the user explicitly assigns a new token (2026-09-05) — `uGitRepoManager.pas`
- Redaction reaches the error dialogs, not just the log. Nineteen `StyledMessageDlg` calls displayed raw `sLog`/`sError` text — the pull handler logged a redacted string and showed the unredacted one in the very next statement — and the dialog is what gets screenshotted into a bug report (2026-09-05) — `MainFrm.pas`
- Redaction covers `Authorization:` headers and masks the live tokens by exact match. A Codeberg/Gitea token is 40 lowercase hex with no prefix, indistinguishable by shape from the commit hashes Git prints constantly, so it could not be matched any other way (2026-09-05) — `uGitRepoManager.pas`
- Plain-text token buffers are zeroed before release, including the DPAPI output blob, so they are not left for a crash dump to pick up (2026-09-05) — `uGitRepoManager.pas`
- Access tokens are stripped of control characters on assignment, as defence-in-depth against header injection from a hand-edited `repositories.json` (2026-09-05) — `uGitRepoManager.pas`
- `git add` is passed `--` before the configured file pattern, so a pattern beginning with `-` is a pathspec rather than an option (2026-09-05) — `uGitRepoManager.pas`
- Range and integer-overflow checking are enabled in the Release configuration. They were Debug-only, so an out-of-range read in the shipped build silently returned whatever followed the array and treated those bytes as string pointers (2026-09-05) — `GitBatchCommit.dproj`

## [1.6.0] - 2026-09-02

### Added

A repository with unmerged paths reported as ordinary *Modified*, so Commit & Push would `git add -A` the conflict markers and push them — `CommitAndPush` now refuses outright while any path is unmerged or a merge/rebase/cherry-pick/revert/bisect is unfinished. And a repository whose work was committed but never pushed reported as *Clean*, with nothing anywhere in the UI saying the remote was out of date (2026-08-30) — `uGitRepoManager.pas`, `MainFrm.pas`, `MainFrm.dfm`
- Ahead/behind commit counts are surfaced in the status text — "Push Required (3)", "Pull Required (2)", "Diverged (+2/-5)" (2026-08-30) — `uGitRepoManager.pas`
- Full DocInsight coverage: every interface declaration across all six units now carries a `/// <summary>`, with `/// <param>` and `/// <returns>` on everything that takes parameters or returns a value — 63 new doc blocks and 50 completed ones. Plain `Sender: TObject` on DFM-wired event handlers is deliberately left undocumented, matching the existing convention; parameters that carry meaning (`Item`, `Key`, `Shift`, dispatching `Sender`) are documented (2026-08-30) — all units

### Fixed
- A commit/push batch aborted after the first repository with `No mapping for the Unicode character exists in the target multi-byte code page`, losing the remaining reindexes and the completion dialog. Captured child-process output was decoded one 4096-byte pipe read at a time, so a multi-byte UTF-8 character straddling a read boundary left an invalid sequence — and `TEncoding.UTF8` is constructed with `MB_ERR_INVALID_CHARS`, so `GetCharCount` returns 0 and `TEncoding.GetString` **raises** instead of substituting U+FFFD. Output is now accumulated as raw bytes and decoded once, through a lenient UTF-8 encoding. **Why:** the failure was intermittent by nature — it only fired when a multi-byte character happened to land on a 4096-byte boundary — so it read as random flakiness (2026-08-30) — `uGitRepoManager.pas`, `MainFrm.pas`
- Every commit message written by the tool began with an invisible UTF-8 BOM, which Git does not strip from a `-F` message file, so every commit subject started with U+FEFF. `CreateCommitMessageFile` now uses the single-argument `TFile.WriteAllText` overload, which writes UTF-8 without a preamble (2026-08-30) — `uGitRepoManager.pas`
- Commit log blocks were attributed to the wrong repository, the first repository never appeared at all, and `UpdateListItem` refreshed the wrong row. Delphi allocates one closure capture frame per **routine**, not per loop iteration, so all the `TThread.Queue` closures created inline in the commit loop shared a single `sCommitLog`/`iRI`, which the worker then overwrote before the UI thread read them. ### Security
- Codeberg and GitHub personal access tokens are now encrypted at rest with DPAPI (current-user scope) before being written to `repositories.json`, and decrypted transparently on load. A token stored in plain text by an earlier build is still read and is re-written protected on the next save. **Why:** the config file previously held usable credentials in clear text under `%APPDATA%`, readable by any process running as the user and carried into every backup and roaming-profile sync (2026-08-30) — `uGitRepoManager.pas`
- Log output is passed through a new `RedactSecrets`, masking the userinfo section of URLs and bare provider token literals. **Why:** Git echoes the remote URL verbatim in most push/fetch errors, so a remote of the form `https://user:token@host` put a live credential into a log the user routinely selects and pastes (2026-08-30) — `uGitRepoManager.pas`, `MainFrm.pas`
- Child processes are launched with an explicit environment setting `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=Never` and empty askpass variables, and with a real (empty) stdin. **Why:** with `STARTF_USESTDHANDLES` set and no stdin handle, a Git operation needing credentials could stall on an invalid handle or raise an interactive Credential Manager dialog behind a hidden window (2026-08-30) — `uGitRepoManager.pas`
